# 真实接口接入说明

`all(1).md` 已转换并导入 Apifox，接口服务前缀为：

```text
http://192.168.168.36:48081/admin-api
```

项目原有的请求已使用 `/system/...` 形式；真实模式会自动拼接为 `/admin-api/system/...`，例如：

```text
/system/creditLimitApply/qryApplyListPage
→ http://192.168.168.36:48081/admin-api/system/creditLimitApply/qryApplyListPage
```

## 启动方式

```bash
pnpm dev:api
```

该命令使用 `.env.real-api`。接口文档已覆盖的请求会直接调用内网接口；文档中未提供的原型接口会自动保留 Mock，避免原型页面因 404 而空白。原来的：

```bash
pnpm dev
```

仍然是本地 Mock 演示模式，便于在没有连接内网或后端临时不可用时继续演示。

## 接入原则

- 先使用 `pnpm dev:api` 验证登录、菜单、客户、项目及授信主链路。
- 接口文档中已存在的路径直接走真实服务。
- 文档未覆盖、或后端暂未交付的原型页面继续保留 Mock 兜底；待后端补充接口后再替换。
- 如后端地址变化，只改 `.env.real-api` 中的 `VITE_BASE_URL`，然后重启前端即可。

## 文档覆盖核对

可将需要验证的前端 API 文件传给下列命令，检查接口文档是否已覆盖：

```bash
node scripts/audit-api-contract-coverage.mjs api-docs/openapi-from-swagger-md.json src/api/creditapplication/creditApplyJob/index.ts src/api/customerInfoMGM/lsgs/index.ts
```

若后端补充了新接口文档，重新生成真实接口清单：

```bash
node scripts/build-real-api-manifest.mjs
```
